# 目标

1. 根据 Jnet 提供的 WebSocket 相关的编解码器，改造 HttpAppServer，实现对 WebSocket 的支持。

# 核心思路

1. **使用 Jnet 提供的 WebSocket 编解码器**：Jnet 框架已经提供了完整的 WebSocket 支持，包括：
   - `WebSocketFrame`：WebSocket 帧的 DTO 类
   - `WebSocketFrameDecoder`：WebSocket 帧解码器（服务端模式）
   - `WebSocketFrameEncoder`：WebSocket 帧编码器（服务端模式）
   - `WebSocketUpgradeDecoder`：自动处理 WebSocket 握手升级的 HTTP 解码器
   - `WebSocketHandshakeUtil`：WebSocket 握手工具类

2. **改造 HttpAppServer 的 Pipeline 初始化逻辑**：
   - 将原有的 `HttpRequestPartDecoder` 替换为 `WebSocketUpgradeDecoder`
   - `WebSocketUpgradeDecoder` 继承自 `HttpRequestPartDecoder`，能够正常处理 HTTP 请求
   - 当检测到 WebSocket 升级请求时，自动发送 101 Switching Protocols 响应并切换到透传模式
   - 透传模式下，后续数据作为 `IoBuffer` 传递给下一个处理器

3. **添加 WebSocket 帧解码和编码处理器**：
   - 在透传模式激活后，后续的原始数据需要通过 `WebSocketFrameDecoder` 解码为 `WebSocketFrame`
   - 用户的自定义 `ReadProcessor<WebSocketFrame>` 可以处理 WebSocket 消息
   - 通过 `WebSocketFrameEncoder` 将 `WebSocketFrame` 编码为字节流发送给客户端

4. **保持向后兼容**：
   - 现有的 HTTP 请求处理逻辑保持不变
   - 现有的处理器（如 `OptionsProcessor`、`ResourceProcessor`、`PathRequestForwardProcessor` 等）会忽略 `WebSocketFrame` 类型的数据
   - WebSocket 相关的处理器会忽略 HTTP 相关的数据类型

5. **提供灵活的配置方式**：
   - 通过 `StartParam` 添加新的配置项来传入 WebSocket 消息处理器
   - 用户可以选择是否启用 WebSocket 支持

# 详细实现思路

## 1. Pipeline 结构设计

### 1.1 原有 Pipeline 结构（仅支持 HTTP）
```
HttpRequestPartDecoder
  -> HttpRequestAggregator
  -> OptionsProcessor
  -> ResourceProcessor (可选)
  -> BeforeProcessor[] (用户自定义)
  -> PathRequestForwardProcessor
  -> NotFoundUrlProcessor (可选)
  -> DataJsonToRespEncoder
  -> HttpRespEncoder
```

### 1.2 改造后的 Pipeline 结构（同时支持 HTTP 和 WebSocket）
```
读处理器链：
WebSocketUpgradeDecoder (替换原 HttpRequestPartDecoder)
  -> HttpRequestAggregator (忽略 IoBuffer)
  -> WebSocketFrameDecoder (解码 IoBuffer 为 WebSocketFrame)
  -> OptionsProcessor (忽略 WebSocketFrame)
  -> ResourceProcessor (可选，忽略 WebSocketFrame)
  -> BeforeProcessor[] (用户自定义，忽略 WebSocketFrame)
  -> WebSocketProcessor[] (用户自定义 WebSocket 处理器，忽略 HttpRequest)
  -> PathRequestForwardProcessor (忽略 WebSocketFrame)
  -> NotFoundUrlProcessor (可选，忽略 WebSocketFrame)

写处理器链：
  DataJsonToRespEncoder (忽略 WebSocketFrame、HttpResponse、IoBuffer)
  -> WebSocketFrameEncoder (编码 WebSocketFrame 为 IoBuffer，透传其他类型)
  -> HttpRespEncoder (编码 HttpResponse 为 IoBuffer，透传 IoBuffer)
```

### 1.3 处理流程说明

**HTTP 请求流程**：
1. `WebSocketUpgradeDecoder` 解析 HTTP 请求头，检测到非 WebSocket 请求，传递 `HttpRequestPartHead`
2. `HttpRequestAggregator` 聚合请求体，传递 `HttpRequest`
3. `WebSocketFrameDecoder` 忽略 `HttpRequest` 类型，直接传递
4. 后续的 HTTP 处理器正常处理请求
5. 响应通过 `DataJsonToRespEncoder` 和 `HttpRespEncoder` 编码后发送

**WebSocket 请求流程**：
1. `WebSocketUpgradeDecoder` 检测到 WebSocket 升级请求：
   - 自动发送 101 Switching Protocols 响应
   - 释放 HTTP 请求头资源
   - 切换到透传模式
   - 后续原始字节数据作为 `IoBuffer` 传递
2. `HttpRequestAggregator` 忽略 `IoBuffer` 类型，直接传递
3. `WebSocketFrameDecoder` 解码 `IoBuffer` 为 `WebSocketFrame`
4. 所有 HTTP 处理器忽略 `WebSocketFrame`，直接传递
5. 用户的 `WebSocketProcessor` 处理 `WebSocketFrame`
6. 响应的 `WebSocketFrame` 通过 `DataJsonToRespEncoder`（透传）
7. `WebSocketFrameEncoder` 编码 `WebSocketFrame` 为 `IoBuffer`
8. `HttpRespEncoder` 收到 `IoBuffer`，直接透传发送

**HTTP 响应流程**：
1. 业务处理器返回普通对象或 `HttpResponse`
2. `DataJsonToRespEncoder` 将普通对象转换为 `HttpResponse`（或透传已有的 `HttpResponse`）
3. `WebSocketFrameEncoder` 收到 `HttpResponse`，直接透传（已在 Jnet 中修改）
4. `HttpRespEncoder` 编码 `HttpResponse` 为 `IoBuffer` 并发送

## 2. StartParam 配置扩展

添加新的配置项：
- `webSocketProcessors`：WebSocket 消息处理器数组
- 保持向后兼容，如果不配置则不启用 WebSocket 支持

## 3. 处理器忽略逻辑

为了保证处理器链的正确性，需要确保：
- HTTP 处理器忽略 `WebSocketFrame` 和 `IoBuffer`（透传场景）
- WebSocket 处理器忽略 `HttpRequest` 和 `HttpRequestPartHead`
- 编码器根据输入类型选择性处理

这可以通过在处理器的 `read()` 方法中添加类型判断来实现。

## 步骤 2：修改 HttpAppServer.start 方法的 Pipeline 初始化逻辑

**文件位置**：`src/main/java/cc/jfire/boot/http/HttpAppServer.java`

在 `start(StartParam param)` 方法中，修改 pipeline 的初始化逻辑：

```java
public static AioServer start(StartParam param)
{
    ChannelConfig            channelConfig = param.getChannelConfig();
    Map<String, PathRequest> requestMap    = parseFromApplication(param.getContext());
    AioServer aioServer = AioServer.newAioServer(channelConfig, pipeline -> {
        // 步骤 2.1：替换 HttpRequestPartDecoder 为 WebSocketUpgradeDecoder
        pipeline.addReadProcessor(new WebSocketUpgradeDecoder());

        // 步骤 2.2：添加 HttpRequestAggregator（已经能正确处理非 HttpRequestPart 类型）
        pipeline.addReadProcessor(new HttpRequestAggregator());

        // 步骤 2.3：添加 WebSocketFrameDecoder（仅当配置了 WebSocket 处理器时）
        if (param.getWebSocketProcessors() != null && param.getWebSocketProcessors().length > 0)
        {
            pipeline.addReadProcessor(new WebSocketFrameDecoder(true)); // true 表示服务端模式
        }

        // 步骤 2.4：添加 OptionsProcessor（已经能正确处理非 HttpRequest 类型）
        pipeline.addReadProcessor(new OptionsProcessor());

        // 步骤 2.5：添加 ResourceProcessor（如果配置了 webDir）
        String                               webDir          = param.getWebDir();
        NotFoundUrlProcessor.NotFoundBarrier notFoundBarrier = null;
        if (StringUtil.isNotBlank(webDir))
        {
            notFoundBarrier = new NotFoundUrlProcessor.NotFoundBarrier();
            pipeline.addReadProcessor(notFoundBarrier);
            pipeline.addReadProcessor(new ResourceProcessor(webDir, RuntimeJVM.detectRunningInJar()==false));
        }

        // 步骤 2.6：添加用户自定义的 HTTP 前置处理器
        if (param.getBeforeProcessor() != null)
        {
            for (ReadProcessor<HttpRequest> processor : param.getBeforeProcessor())
            {
                pipeline.addReadProcessor(processor);
            }
        }

        // 步骤 2.7：添加用户自定义的 WebSocket 处理器
        if (param.getWebSocketProcessors() != null)
        {
            for (ReadProcessor<WebSocketFrame> processor : param.getWebSocketProcessors())
            {
                pipeline.addReadProcessor(processor);
            }
        }

        // 步骤 2.8：添加 PathRequestForwardProcessor（需要确保能忽略 WebSocketFrame）
        pipeline.addReadProcessor(new PathRequestForwardProcessor(requestMap));

        // 步骤 2.9：添加 NotFoundUrlProcessor（如果配置了 webDir）
        if (StringUtil.isNotBlank(webDir))
        {
            pipeline.addReadProcessor(new NotFoundUrlProcessor(notFoundBarrier));
        }

        // 步骤 2.10：添加写处理器
        pipeline.addWriteProcessor(new DataJsonToRespEncoder()); // 已经能正确处理 IoBuffer

        // 步骤 2.11：添加 WebSocketFrameEncoder（仅当配置了 WebSocket 处理器时）
        if (param.getWebSocketProcessors() != null && param.getWebSocketProcessors().length > 0)
        {
            pipeline.addWriteProcessor(new WebSocketFrameEncoder(pipeline.allocator(), false)); // false 表示服务端模式
        }

        pipeline.addWriteProcessor(new HttpRespEncoder(pipeline.allocator()));
    });
    aioServer.start();
    return aioServer;
}
```

```java
@Override
public void write(Object data, WriteProcessorNode next)
{
    if (data instanceof HttpResponsePart
        || data instanceof HttpResponse
        || data instanceof IoBuffer
        || data instanceof DataIgnore
        || data instanceof WebSocketFrame) // 新增：忽略 WebSocketFrame
    {
        next.fireWrite(data);
    }
    else
    {
        HttpResponse httpResponse = new HttpResponse();
        httpResponse.setBodyText(Dson.toJson(data));
        next.fireWrite(httpResponse);
    }
}
```
